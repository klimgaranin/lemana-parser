## Текущая договорённость с пользователем
- Разработка может идти через WSL Ubuntu и VS Code, но рабочая среда проекта — Windows.
- Проект должен быть удобен для Git: клонировать на Windows-компьютер, настроить `.env`, запустить `.bat`-скрипты и получить Excel.
- Для Codex CLI контекст проекта хранится в `.codex/`.
- Перед новой задачей агент обязан перечитать проектную память.
- Сначала делаем надёжную основу, потом удобства и рефакторинг.
- Пользователь не любит мусор в проектах: периодически чистить артефакты, случайные файлы и устаревшие заметки.
- Предпочтение — модульная структура, понятные типизированные имена файлов и единый стиль похожих модулей.

## Ближайшие шаги
- Держать Windows-first документацию и команды запуска актуальными.
- Модульная структура пакета `lemana_parser/` подготовлена; дальше расширять её без возврата к куче файлов в корне.
- Windows `.bat`-скрипты запускают Python напрямую из `.venv\Scripts\python.exe`.
- Локальная основа покрыта тестами парсинга, конфигурации и Excel-выгрузки.
- Упаковку в `.exe` отложить до полной готовности проекта.
